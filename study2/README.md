# Study 2

This folder holds everything for Study 2: the task as it ran on Pavlovia (`experiment/`, with its own README), the processed data, the justification-coding protocol with an archive of every model response, the registered analysis and its report, two analyses that are not part of the registration, and the combined report that writes the tables and figures of the revised manuscript for both studies. It is an RStudio project. Open `study2_analysis.Rproj`, or set R's working directory to this folder, before running any R script; every script uses paths relative to this folder.

## The order of the steps

The steps ran in the order of the Study 2 analysis plan. `01a_exclusions.R` and `01b_assemble_tables.R` applied the registered exclusions and built the tables, `02a_check_set.py` drew the check set for hand coding, `02b_coding_protocol.ipynb` froze the coding protocol and coded the justifications, `03_masked_data.R` made the masked data sets on which the analysis script was built and tested, and `04_freeze.R` froze the script. `MPC_Study2_Analysis.Rmd` was then knitted on the real data, on October 8, 2026. Only after that were the machine learning notebook (`05_nlp_study2.ipynb`) run and the combined report (`06_combined_report.Rmd`) knitted, because both read the outcomes. The scripts were written so that nothing before the freeze displays a Study 2 outcome: the Stage 1 scripts print only counts and structural checks, the coding notebook prints no Study 2 justification, code or count of codes, and the analysis script was developed on masked data only.

## What is posted and what is not

`data/processed/study2_trials.csv` has one row per case (1,310 rows). It gives the participant code, whether the participant was among the first 200 to complete the study, the position of the case, the vignette and its six features, the name, town and country shown, the choice and its response time, the slider rating with its starting position and response time, the written justification and its response time, and the answers to the three element questions (`knew`, `aware`, `should`) with their response time. `data/processed/study2_participants.csv` has one row per participant (262 rows). Among its columns are completion order and duration, the eligibility answer, the comprehension item (the answer, its option order, and whether it came before or after the element questions), age, gender, race, education, jury service, legal training, the ranking of the four descriptions, the Raven's matrices items and score, and the order of the cases. Participant codes run in order of completion (P001 is the first person to complete the study), so the codes of the 262 analysed participants have gaps where the nine excluded completers were. `data/processed/justification_codes.csv` gives the code assigned to each of the 2,370 justifications in both studies and the inference model's awareness-denied flag.

`data/study1_trials.csv` is an identical copy of the Study 1 data file (`study1/data/modeling_mental_states_analysis_part3.csv` in this repository), kept here so that the folder runs on its own, and `data/study1_names.csv` gives the defendant's name in each of the 1,060 analysed Study 1 cases, which the Study 1 file does not record and the coding prompt uses. `materials/mensReaVignettes_binary.json` holds the 64 vignettes; it is identical to the Study 1 file.

`protocol/` holds the check set (the key, the items, the blank and completed coding sheets, and the hand codes as a table), the coding prompt (the system prompt, the template and the fourteen examples), the freeze record of the coding protocol (`coding_freeze.json`), every raw model response (`llm_raw/`) and inference result (`nli_raw/`), the check-set results (`check_set_results.csv` and `check_set_llm_codes.csv`), the run log, and the freeze record of the analysis script (`analysis_freeze.txt`). `output/` holds the Stage 1 logs and flow table, the reports, and their figures in color and grayscale.

`experiment/` holds every file of the task, the vignette counts at launch, and the function that kept the counts up to date during data collection. Its README describes the session and the data it writes, and records how the copy was checked against the study's Pavlovia project: the files are identical except that the three Prolific completion codes are redacted.

Some files are not posted. The 302 raw Pavlovia session files and Prolific's export of submissions carry Prolific IDs, and the export also carries Prolific's own demographic data. The three Stage 1 tables that carry Prolific IDs (`study2_sessions.csv`, `study2_exclusions.csv` and `prolific_followup.csv`) are also held back, as are the Study 1 session files that `02a_check_set.py` reads for the defendants' names. The masked data sets are not posted because `03_masked_data.R` regenerates them exactly. During masked review the protocol freeze bundle (`protocol/coding_freeze_bundle.zip`) is held back too, because its copy of the coding notebook records file paths that would identify the authors. Every other file in the bundle is posted unchanged in `protocol/`, and the code of its notebook is the code of the posted `02b_coding_protocol.ipynb` except for the line that confirms the bundle was posted. Before posting, the justifications and the open-ended answers were screened for names, contact details and anything else that could identify a participant.

## Rerunning the analyses

The registered analysis needs R with dplyr, readr, tidyr, purrr, stringr, tibble, jsonlite, lme4, lmerTest, ordinal, geepack, ggplot2, knitr, kableExtra, rmarkdown, diptest and mclust. The header of `MPC_Study2_Analysis.Rmd` already sets `data_source: "real"`, so it can be knitted from RStudio, or from a terminal in this folder:

```
Rscript -e "rmarkdown::render('MPC_Study2_Analysis.Rmd', params = list(data_source = 'real'), output_file = 'output/MPC_Study2_Analysis_real.html')"
```

A knit takes about ten minutes, most of it the 5,000-resample bootstraps. The script reads the real data only when it and `R/study2_functions.R` still match the checksums in `protocol/analysis_freeze.txt` (the checksum ignores the `data_source` line). On Windows the check may fail even for unchanged files, because R writes Windows line endings when it computes the checksum there, so knit on macOS or Linux.

The two masked reports are rebuilt by writing the masked data and knitting the same script on it:

```
Rscript 03_masked_data.R
Rscript -e "rmarkdown::render('MPC_Study2_Analysis.Rmd', params = list(data_source = 'simulated'), output_file = 'output/MPC_Study2_Analysis_simulated.html')"
Rscript -e "rmarkdown::render('MPC_Study2_Analysis.Rmd', params = list(data_source = 'structure'), output_file = 'output/MPC_Study2_Analysis_structure.html')"
```

The combined report reads the processed data, `data/study1_trials.csv` and the notebook's tables in `output/nlp`, and knits in about two minutes:

```
Rscript -e "rmarkdown::render('06_combined_report.Rmd', output_dir = 'output/combined')"
```

The two notebooks ran in Google Colab. To rerun one, copy this folder to Google Drive, open the notebook from there, set `FOLDER_IN_DRIVE` in its first code cell to the folder's path, choose a GPU runtime and run all cells. `05_nlp_study2.ipynb` takes about twenty-five minutes. `02b_coding_protocol.ipynb` reproduces the coding from the archive: every response is saved in `protocol/llm_raw/` and every inference result in `protocol/nli_raw/`, so a rerun sends no request, and its last part rebuilds `data/processed/justification_codes.csv` from the archive and confirms that the rebuilt file is identical. The notebook still asks for an Anthropic API key when it starts.

`01a_exclusions.R`, `01b_assemble_tables.R` and `02a_check_set.py` cannot be rerun from this repository, because their inputs are among the files held back. They are posted so that the exclusion rules and the check-set draw can be read, and the flow of participants they produced is in `output/stage1_flow.csv`.

## Stage 1: exclusions and tables

`01a_exclusions.R` is the registered exclusion script. It read only the exclusion variables from the 302 Pavlovia files and only the status and time columns from Prolific's export, and applied the registered rules: complete sessions only, the attention item, the seriousness item, the speed rule (a third of the median completion time of the first 40 completions), and the duplicate rule. Of the 337 submissions in Prolific's export, 271 people completed the study. The primary analyses use the full sample, every completed session that passes the exclusions (262 people, after 8 failed the attention item and 1 said they had not taken the study seriously). The first 200 completions, the sample the registered stopping rule implies, are flagged for a robustness analysis (193 people after exclusions). `01b_assemble_tables.R` read the complete files of the people in the full sample, and nobody else, and wrote the trial and participant tables. It checks twelve structural facts, including that the text each participant saw matches the vignette file for every case, and stops if any fails; its console output is those checks and nothing else.

Completion time is each session's length on the study's own clock. jsPsych restarts that clock when the main part of the study loads, so the script adds the two parts. Pavlovia names each file with the time it was saved, on the participant's computer and in their time zone, so file names cannot order sessions across people. The order of completion is therefore put on Prolific's clock: each session ends at the person's Prolific start time plus the time that passed on their own computer from the start of their first session to the end of this one. Ordering by the time Prolific recorded the completion code, where there is one, gives the same first 200.

## Stage 2: coding the justifications

`02a_check_set.py` drew the registered check set: 100 Study 1 justifications (60 Knowledge, 20 Recklessness, 10 Negligence, 10 Blamelessness) from the 1,060 analysed Study 1 cases, with numpy's default generator and seed 20261007, in random order. It wrote the key (`protocol/check_set_key.csv`), the items with the defendant's name and the justification (`protocol/check_set_items.csv`) and the coding sheet. The completed sheet is `protocol/check_set_hand_codes.xlsx`, and the same codes as a plain table, which the coding notebook reads, are `protocol/check_set_hand_codes.csv`.

`02b_coding_protocol.ipynb` carries out the registered coding protocol. The language model is Claude Opus 4.6 (`claude-opus-4-6`) at temperature 0, with structured output limited to the seven codes. The registration requires temperature 0, and Anthropic's newer models reject any temperature setting, so Opus 4.6 was the most capable model that met the registration; from the 4.6 generation on, each Anthropic model identifier names one fixed snapshot. The prompt (`protocol/coding_system_prompt.txt`, built from `protocol/coding_prompt_template.txt`) holds the registered codebook and the four rules of the hand-coding sheet word for word, followed by five clarifications added before the freeze (rules 5 to 9), and fourteen examples (`protocol/coding_examples.csv`, two per code, all Study 1 justifications outside the check set). Each request sends only the defendant's name and the justification. The cross-check is the registered inference model, DeBERTa-v3-large (`MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli` at commit `b3546ea6`), with the registered premise, hypotheses and rule.

The notebook runs in four parts. Part A sends one test request with an example text and freezes the protocol: `protocol/coding_freeze.json` records the settings and the checksums of the prompt, the examples, the check-set key and the hand codes, with the time. After the freeze, any change to those stops the notebook before anything is sent. Part B coded the 100 check-set texts once and wrote the kappas to `protocol/check_set_results.csv` (knowledge stated within the 60 Knowledge items, .78; awareness denied across all 100, .83; both above the registered threshold of .60; all seven codes, .80). Part C coded all 1,060 Study 1 and 1,310 Study 2 justifications, ran the cross-check, and wrote `data/processed/justification_codes.csv` and `protocol/coding_run_log.json`. Part D rebuilt the codes file from the archived raw outputs and confirmed that it was identical. Before the real run, the notebook was tested end to end against a stand-in for the API that checked every request body and injected temporary errors, on a test copy of the folder whose texts were stand-ins drawn from Study 1 justifications outside the check set.

## Stages 3 and 4: the analysis script, masked data, freeze and the real run

`MPC_Study2_Analysis.Rmd` carries out every registered analysis in the order of the registration: H1, H2 and V1 with the registered fallback rule, the five sensitivity analyses, R1 to R5 with the R1 to R4 Holm family, and S1 to S11, labeled exploratory. A robustness check on the first 200 completions, model notes and the deviations table close it. Its functions are in `R/study2_functions.R`. Each Study 2 estimate is shown next to its Study 1 counterpart, recomputed from `data/study1_trials.csv` with the same code, and the recomputation reproduces the published Study 1 values.

`03_masked_data.R` writes two masked data sets. The simulated set resamples Study 1 participants and generates element answers and justification codes under the registered misreading scenario, so the script should recover known effects. The structure set keeps the real Study 2 design and covariates and replaces every outcome with simulated values, so it tests the script on the real design while carrying no Study 2 result. The script was built and checked on both, and their reports are in `output/`.

`04_freeze.R` recorded MD5 checksums of the Rmd and the functions file in `protocol/analysis_freeze.txt` on October 8, 2026, at 16:13 Pacific time. The Rmd reads the real data only when both files match those checksums and the bootstrap uses 5,000 resamples, so any later edit blocks the real run. The run on the real data followed the same day, and its report is `output/MPC_Study2_Analysis_real.html`.

## Not registered: the Study 1 machine learning analyses on Study 2

`05_nlp_study2.ipynb` repeats on Study 2 the analyses of the Study 1 notebook (`study1/analysis/MPC_NLP_SHAP_Analysis_2_0.ipynb` in this repository), section by section and with the same code: random forests that predict the choice from the six features with and without the slider rating, SHAP importance overall and by category, BGE-large and MiniLM embeddings of the 64 vignettes, UMAP, the representational similarity analysis, and the justification analyses (UMAP, BERTopic, the text classifier, and the combined feature and text model). None of it is in the preregistration. It uses the Study 1 seed and settings, pins scikit-learn 1.6.1, shap 0.51.0, sentence-transformers 5.3.0, umap-learn 0.5.11, bertopic 0.17.4 and hdbscan 0.8.44, and pins both embedding models to fixed revisions. It runs the same code on the Study 1 data as well, and that rerun reproduces the published Study 1 values, so differences between the studies come from the data, not the code. Its additions, each labeled in the notebook, are the category defined by the element answers as a second outcome, a participant bootstrap of the SHAP ranking, the plain percentages behind the Knowledge importances, a permutation p value for the similarity analysis, the correlation of vignette means across the studies, and a replication table. Its figures are in `output/nlp/figures` (prefix `fig_s2_`), its tables in `output/nlp`, and a copy with all outputs in `output/nlp/05_nlp_study2.html`. It prints no individual justification.

## Not registered: the combined report

`06_combined_report.Rmd` gathers what the revised manuscript reports for both studies. It writes the manuscript's tables, as LaTeX and as CSV, to `output/combined/tables`, and its three new figures to `output/combined/figures`. It adds no registered analysis and changes none. The registered Study 2 numbers it uses are recomputed with the frozen functions file and the registered code and seeds, and its third section checks 35 of them against the frozen report; in the knit posted here (`output/combined/06_combined_report.html`, October 9, 2026, on the computer of the registered run) all 35 match. On another computer two Study 1 odds ratios can differ in their third decimal, as iterative model fits can, and the report labels such a case "last digit" rather than a mismatch. The report also computes two exploratory analyses that reviewers asked about: the share of participants in each study who ranked the four descriptions in the Code's order, and the registered inquiry-carryover analysis (S6) run on Study 1.

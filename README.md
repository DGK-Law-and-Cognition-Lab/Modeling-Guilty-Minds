# Modeling Guilty Minds

This repository holds the data, experimental materials and analysis code for the two studies reported in the manuscript "Modeling guilty minds," which is under masked review. Author and institutional details are withheld until the review is complete.

## The studies

Both studies ask whether laypeople sort a defendant's mental state into the Model Penal Code's categories when they have to infer it from the facts of a case rather than read it from a label. In every case a man agrees to carry a package across a national border, and six binary features vary across 64 versions of the case: who asks him (his uncle or a biker), the package (gift-wrapped or a duffel bag), how he learns about the contents (the source tells him without being asked, or he asks), payment ($1,000 or none), the border (Canada or Mexico), and what the package holds (fentanyl, or a medicine for a rare disease that is not approved in the United States). Each participant judged five cases. For each case they chose which of four descriptions the scenario proved beyond a reasonable doubt (the descriptions correspond to Knowledge, Recklessness, Negligence and Blamelessness, and were shown without those labels), rated on a 0 to 100 slider how certain the man was that the package held illicit material, and explained their choice in writing.

Study 1 (212 undergraduates from a university participant pool, 1,060 cases) found that Knowledge choices came with lower certainty ratings than Recklessness choices, the reverse of the order the Code implies. Study 2 (262 jury-eligible US adults recruited through Prolific, 1,310 cases) repeated the Study 1 task unchanged and then showed each case again with three yes-or-no questions about the elements: whether the scenario proved beyond a reasonable doubt that, when he crossed the border, the man knew or was practically certain that illicit material was in the package; that he was aware of a substantial risk that it was; and that a reasonably careful person in his position would have been aware of that risk.

## Layout

Each study has its own folder. The Study 1 files keep the names they had in the original submission, now under `study1/`. The Study 2 folder is a self-contained RStudio project with its own README.

```
index.html        the project page, with links to every rendered report
study1/
  experiment/     the task (jsPsych, run on Pavlovia) and the 64 vignettes
  data/           the trial data, one row per case
  analysis/       the analyses, each with its rendered HTML report
  figures/        the figures, in color and grayscale
study2/           the task, data, justification-coding protocol and archive, the registered
                  analysis, the unregistered analyses, and the combined report that produces
                  the tables and figures of the revised manuscript for both studies
```

The `.html` files are self-contained reports with the code, output and session information of the run that produced them. To read one, download it and open it in a browser.

## Study 1

`study1/data/modeling_mental_states_analysis_part3.csv` has one row per case for every session that reached the cases (1,081 rows from 230 sessions). The analysis keeps the 212 participants who completed all five cases, 1,060 cases in all. The columns give the session, the vignette and its six features, the position of the case in the session, the choice, the slider rating, the written justification, response times, the Raven's matrices score, the ranking of the four descriptions given at the end of the session, and age, education and legal experience. `session_id` is a session code generated by the experiment platform, not a participant identifier.

`study1/experiment/` holds the task as it ran: `index.html` loads it, `experiment.js` defines the timeline, `trialMinimisation.js` chooses each participant's five cases so that the 64 versions stay balanced across the sample, `style.css` styles it, and `mensReaVignettes_binary.json` holds the 64 vignettes. The Raven's matrices items and images, which are the same in both studies, are in `study2/experiment/rpm/`.

`study1/analysis/MPC_MainAnalysis_Updated.Rmd` carries out the cumulative link mixed models, the threshold-specific models and the other analyses in R, and `study1/analysis/MPC_PowerAnalysis.Rmd` the power analysis. `study1/analysis/MPC_NLP_SHAP_Analysis_2_0.ipynb` is the Python notebook for the random forests, SHAP values, representational similarity analysis, BERTopic and the justification classifier; it ran in Google Colab. Each has a rendered HTML report beside it. The R Markdown file reads the data from the path set in `DATA_PATH` near its top, and the notebook from the Google Drive paths in its setup cell, so point those at your copy of the data file before running them.

## Study 2

Everything for Study 2 is in `study2/`, and `study2/README.md` describes each step in detail. The task itself, as it ran on Pavlovia, is in `study2/experiment/`, whose README describes the session and the data it writes. In brief, the analysis steps ran in this order. `01a_exclusions.R` and `01b_assemble_tables.R` applied the registered exclusions to the raw session files and built one table of cases and one of participants, with participant codes (P001 is the first person to complete the study) in place of Prolific IDs. `02a_check_set.py` drew the registered check set of 100 Study 1 justifications for hand coding. `02b_coding_protocol.ipynb` froze the justification-coding protocol and coded all 2,370 justifications from both studies with Claude Opus 4.6 (`claude-opus-4-6`) at temperature 0, scored its agreement with the hand codes on the check set, and ran the registered cross-check with an inference model (DeBERTa-v3-large). `03_masked_data.R` made two masked data sets on which the analysis script was built and tested without any Study 2 outcome. `04_freeze.R` recorded checksums of the analysis script and its functions file, and `MPC_Study2_Analysis.Rmd` was then run on the real data; it refuses to read the real data unless both files match the checksums in `study2/protocol/analysis_freeze.txt`. Its report is `study2/output/MPC_Study2_Analysis_real.html`.

Two later steps are not part of the registration. `05_nlp_study2.ipynb` repeats the Study 1 notebook's machine learning analyses on Study 2 with the same code, settings and pinned package and model versions. Run on the Study 1 data, the same code reproduces the published Study 1 values. `06_combined_report.Rmd` gathers the results of both studies into the tables and figures of the revised manuscript, recomputes 35 registered Study 2 numbers with the frozen code and checks them against the frozen report (all 35 match), and adds two exploratory analyses that reviewers asked about.

From this repository you can rerun the registered analysis, the combined report and the machine learning notebook, and rebuild the justification codes from the archived model responses without sending any new request. The two Stage 1 scripts and the check-set script are posted so that they can be read, but they cannot be rerun from here, because their inputs (the raw Pavlovia session files, Prolific's export of submissions, and the Study 1 session files) carry Prolific IDs or other session records that are not shared. The exclusion flow they produced is in `study2/output/stage1_flow.csv`.

## Software

The Study 1 R reports, the registered Study 2 run and the combined report ran on R 4.5.2, and every R report ends with its full session information. The notebooks ran in Google Colab. The Study 1 notebook prints the Python and package versions it used in its last cells, and the Study 2 notebooks record theirs in `study2/output/nlp/session_info.txt` and `study2/protocol/coding_run_log.json`.
